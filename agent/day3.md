# Day 3 — 정신력 · 인벤토리 · 증거 · 기록노트 · 휴대폰 · 조건 분기

> gamd.md 대응: 8~13장, 14장(세로 슬라이스)

## 오늘의 목표

Day 2의 뼈대 위에 **게임을 게임답게 만드는 5개 시스템**을 얹고,
프롤로그 ~ 2장까지를 실제로 플레이 가능한 세로 슬라이스로 완성한다.

---

## 1) 정신력 시스템 (1h)

```text
maxMental = 100 / currentMental = 100
```

감소 (`public/data/` 수치로 관리, 코드 상수 금지):

| 사건 | 변화 |
|------|------|
| 이상한 문자 확인 | -5 |
| CCTV 확인 | -10 |
| 자신의 사진 발견 | -10 |
| 밤에 회사에 남기 | -15 |
| 합성 사진 발견 | -20 |
| 정체불명의 목소리 | -10 |

회복: 의문의 커피 +10 / 따뜻한 차 +8 / 비상 안정제 +20 / 음성 메모 +15

- [ ] 구간 판정 함수: `안정(80~100) / 불안(60~79) / 집중저하(40~59) / 손떨림(20~39) / 판단어려움(0~19)`
- [ ] `MentalState` UI — 숫자 + 구간 라벨 (막대 스타일은 Day 4)
- [ ] 구간별 텍스트 변형 훅 `useMentalFilter(text)` 자리만 만들어 둔다 (연출은 Day 4)
- [ ] **핵심 원칙: 기록 노트의 증거 원문은 절대 왜곡하지 않는다** — 필터 적용 예외 처리
- [ ] 단위 테스트: 0/100 클램프, 구간 경계값(19/20, 59/60, 79/80)

## 2) 인벤토리 + 아이템 사용 (1h)

- [ ] `I` → 인벤토리, 아이템/증거/특수자료 3탭
- [ ] `items.json` 기반 렌더 (이름, 설명, 사용 가능 여부)
- [ ] `itemUse` 이벤트 타입 구현

```text
비상 안정제 사용 → 정신력 +20 → flag: stabilizer_used → 흐린 파일 열람 조건 충족
```

- [ ] 사용 시 소모/비소모 구분
- [ ] 사용이 이벤트를 트리거할 수 있어야 한다 (`onUse: eventId`)

## 3) 증거 시스템 (1h)

3 카테고리:

```text
MEMORY   — 07:48 커피 알림, 22:28 자동 문자, MEMORY_01, 삭제된 메모, 02:13 백업, 과거 음성 메모
인물 관련 — 대리 / 팀장 / 옆자리 직원 / 경비원 / 동기
사건 관련 — CCTV, 사내망 접속 기록, 사진·합성사진 출력 기록, 야간 출입 정보, 손상된 백업 파일
```

- [ ] `evidence.json` 에 위 항목 전부 정의 (id / category / title / detail / relatedCharacter)
- [ ] `EvidenceList` — 카테고리 탭, `EvidenceDetail` — 원문 전문
- [ ] 인물 단서는 `characterClues`에 **인물별로** 집계 (진 엔딩 조건이 "서로 다른 인물 2명"이므로 인물 단위 카운트 필수)
- [ ] 중복 획득 방지

## 4) 기록 노트 시스템 (1h)

```json
{
  "id": "note_coffee_order",
  "fact": "07:48에 내 이름으로 로비 커피 주문이 등록됐다.",
  "assumption": "누군가 내 계정으로 주문하고 내 자리에 두었다.",
  "nextCheck": "주문과 전달을 같은 사람이 했는가?"
}
```

- [ ] `RecordNote` UI — 사실 / 추측 / 다음 확인 3단 구분 렌더
- [ ] 획득 순서대로 정렬, 챕터별 그룹핑
- [ ] 정신력 저하 연출의 **면역 구역** (사실 텍스트는 항상 원문)

## 5) 휴대폰 시스템 (1.5h)

```text
Phone
├── 문자        MessageList
├── 기록 노트    RecordNote
├── 사진        PhotoList
├── 음성 메모    VoiceMemo
└── 삭제된 항목  DeletedList (복구 조건 필요)
```

- [ ] Tab 토글, 탭 전환
- [ ] 문자 수신을 이벤트로 push (`messageReceive` 효과 타입) — 신규 알림 배지
- [ ] 삭제된 항목은 `recovered_deleted_note` / `recovered_voice_memo` 플래그로 잠금 해제
- [ ] 휴대폰을 여는 것 자체가 이벤트 트리거가 될 수 있게 (`onPhoneOpen` 훅)

## 6) 조건 / 분기 시스템 — ConditionManager (1.5h)

```json
{
  "conditions": [
    { "type": "evidence_count", "category": "MEMORY", "min": 2 },
    { "type": "character_clue_count", "min": 2 },
    { "type": "flag", "key": "intrusion_evidence", "value": true }
  ]
}
```

- [ ] `ConditionManager.evaluate(conditions, gameState): boolean` — 순수 함수, 테스트 최우선 대상
- [ ] 지원 타입: `flag` / `evidence_count` / `character_clue_count` / `has_item` / `mental_below` / `mental_above`
- [ ] `condition` / `branch` 이벤트 타입 구현 (조건 → 서로 다른 next)
- [ ] 선택지 조건부 노출 (`conditions` 미충족 시 숨김 또는 비활성 + 사유)
- [ ] 단위 테스트: 진 엔딩 조건 조합을 그대로 테이블 테스트로 작성

## 7) 세로 슬라이스 데이터 작성 (2h)

`퇴근하지_마세요_최최종본.txt`에서 옮긴다.

```text
프롤로그 → 1장 평범한 월요일(커피) → CCTV 조사 → 2장 이상한 문자
```

- [ ] `prologue.json` `chapter01.json` `chapter02.json`
- [ ] 이 구간에서 발생하는 정신력 변화 / 증거 / 노트 / 플래그를 전부 데이터로 연결
- [ ] 조사 순서 흐름 검증: `CCTV 조사 → MEMORY_01 → 사내망 기록`

## 완료 기준 (실제로 끝까지 플레이)

- [ ] 프롤로그부터 2장 끝까지 **한 번도 코드로 개입하지 않고** 진행된다
- [ ] 다음 9요소가 한 흐름 안에서 전부 동작한다
      `이동 → 상호작용 → 이벤트 → 대화 → 선택 → 정신력 → 증거 → 기록 → 분기`
- [ ] CCTV를 조사한 플레이와 조사하지 않은 플레이의 **후속 선택지가 실제로 다르다**
- [ ] 정신력을 40 아래로 떨어뜨렸을 때 UI 구간 표시가 바뀐다
- [ ] 휴대폰에서 획득한 증거·노트를 전부 다시 확인할 수 있다
- [ ] `npm run test` — ConditionManager 테이블 테스트 통과
- [ ] `npm run build` 성공 — 시스템 6개를 얹는 동안 클라이언트 전용 코드가 서버로 새지 않았는지 확인
