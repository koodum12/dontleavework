# Day 6 — 캐릭터 · NPC · 맵 디자인

> gamd.md 대응: 17장(디자인/연출), 19장(assets/), 10장(인물 단서)
> 전제: Day 5의 장소 이동과 `events/index.json` 이 끝나 있어야 한다

## 오늘의 목표

지금 사무실에는 **사람이 없다.** 대리·팀장·옆자리 직원은 "책상 오브젝트"로만 존재하고,
말을 거는 게 아니라 가구를 조사하는 형태다. 인물 단서가 엔딩 조건인 게임에서 이건 치명적이다.

```text
지금: 색 사각형 10개(가구) + 흰 사각형(플레이어)
목표: 서 있는 NPC · 상황에 따라 바뀌는 맵 · 4방향 스프라이트
      그리고 이 전부를 JSON으로 배치·수정할 수 있는 상태
```

## 1) 제작 원칙 — 아티스트 없이 만든다 (0.2h)

그림을 잘 그리는 것보다 **한 눈에 구분되는 것**이 먼저다. 순서를 지킨다.

```text
1단계  색 사각형 + 이름표    ← 지금. 배치와 동선을 여기서 확정한다
2단계  32×32 도트 스프라이트  ← 실루엣 + 색 2~3개. 얼굴은 그리지 않는다
3단계  4방향 × 2프레임 걷기   ← 여유가 있을 때만
```

- 배치가 확정되기 전에 그림을 그리면 두 번 그린다. **1단계에서 플레이 테스트를 끝낸다**
- 캐릭터는 **색 하나로 구분**한다 (대리=회색 셔츠, 경비원=남색…). 스토리에 "회색 셔츠"가 단서로 나오므로 색이 곧 정보다
- 픽셀 단위는 32px 그리드 (`TILE = 32`). 캐릭터는 24×32, 히트박스는 24×24로 통일
- 이미지가 없으면 색 사각형으로 그린다. **에셋 유무가 진행을 막지 않게** 렌더러가 폴백을 갖는다

## 3) NPC — 사람을 맵에 세운다 (2.5h)

가구(`objects`)와 사람(`npcs`)을 분리한다. **사람은 조건에 따라 자리를 옮기고 말이 바뀐다.**

### `public/data/npcs.json`

```jsonc
{
  "npc_daeri": {
    "id": "npc_daeri",
    "characterId": "daeri",          // characters.json 참조 (이름·색을 여기서 가져온다)
    "location": "office",            // 어느 맵에 서 있나
    "x": 848, "y": 470,
    "facing": "down",
    "solid": true,                   // 통과 불가 (사람도 벽이다)
    "eventId": "talk_daeri",         // 말 걸었을 때 (없으면 idle 대사만)
    "idle": "대리는 모니터를 보고 있다.",
    "conditions": [                  // (선택) 이 조건일 때만 이 자리에 있다
      { "type": "flag", "key": "chapter3_done", "value": false }
    ]
  },

  "npc_daeri_night": {               // 같은 사람의 다른 상황 배치
    "id": "npc_daeri_night",
    "characterId": "daeri",
    "location": "corridor",
    "x": 320, "y": 200,
    "eventId": "ch6_ask_daeri",
    "conditions": [{ "type": "flag", "key": "found_composite", "value": true }]
  }
}
```

### 규칙

- **한 캐릭터가 여러 NPC 엔트리를 가질 수 있다** — 같은 사람이 상황에 따라 다른 장소에 선다
- 조건이 겹치면 파일 순서상 **먼저 나온 것** 하나만 등장 (여러 명이 복제되지 않게)
- `solid: true` 면 충돌 대상에 포함 — `PlayerController.solidRects()` 가 NPC도 받는다
- 말 걸기는 기존 상호작용 그대로 (`E`, 최근접 1개, 경계 거리 48px)

### 구현 체크리스트

- [ ] `Npc` 타입 + `npcs.json` 로더 + `useGameData` 에 추가
- [ ] `InteractionManager.findNearest()` 가 오브젝트와 NPC를 **한 후보 목록**으로 본다
- [ ] `Renderer` 에 NPC 그리기 (캐릭터 색 사각형 + 방향 표시, 스프라이트 있으면 스프라이트)
- [ ] 프롬프트는 `E - 대리에게 말을 건다` 형태 (가구는 `조사하기`, 사람은 `말을 건다`)
- [ ] `solidRects()` 에 solid NPC 포함 — 맵 로드 시점이 아니라 **조건 평가 후** 목록을 만든다
- [ ] 조건이 바뀌면(플래그 변화) NPC 목록을 다시 계산 (매 프레임 전체 재평가는 금지, 플래그 변경 시에만)

### 기존 데이터 이관

- [ ] `obj_desk_daeri` `obj_desk_team_leader` `obj_desk_neighbor` 의 `eventId` 를 NPC 로 옮긴다
      (책상은 가구로 남기고, 말 걸기는 사람에게)
- [ ] `obj_security_desk` → `npc_guard`, `obj_water` 앞 → `npc_peer`
- [ ] 이관 후 `npm run validate` 로 끊긴 참조 확인

## 4) 상황별 맵 — 같은 장소의 다른 상태 (2h)

3장의 낮 사무실과 6장의 야간 사무실은 **같은 맵이지만 다른 장면**이다.
맵을 복제하지 않는다. 복제하면 한쪽만 고치는 사고가 난다.

### 방법: 오브젝트/NPC에 조건 + 맵 팔레트 오버라이드

```jsonc
{
  "office": {
    "id": "office",
    "name": "사무실",
    "palette": "day",                       // 기본 팔레트
    "variants": [                            // 조건을 만족하면 팔레트만 바뀐다
      {
        "id": "night",
        "palette": "night",
        "nameSuffix": " (야간)",
        "conditions": [{ "type": "flag", "key": "chapter6_started", "value": true }]
      }
    ],
    "objects": [
      {
        "id": "obj_printed_photo",
        "label": "출력함 위의 사진",
        "x": 832, "y": 250, "w": 24, "h": 24, "solid": false,
        "eventId": "ch6_printer",
        "conditions": [{ "type": "flag", "key": "found_composite", "value": false }]
      }
    ]
  }
}
```

### `public/data/palettes.json`

```jsonc
{
  "day":   { "floor": "#23262c", "wall": "#4a5058", "object": "#6b563c", "grid": "#2b2f36" },
  "night": { "floor": "#15171c", "wall": "#33383f", "object": "#4a3b2a", "grid": "#1c1f24" },
  "home":  { "floor": "#241f22", "wall": "#3d3439", "object": "#6b4f45", "grid": "#2a2429" }
}
```

- [ ] `Renderer` 의 하드코딩 `COLORS` 를 팔레트 데이터로 교체 (플레이어·강조색은 공용 유지)
- [ ] `MapObject.conditions` 지원 — 조건 미충족이면 **그리지도, 충돌하지도, 상호작용하지도 않는다**
- [ ] `GameMap.variants` — 위에서부터 조건을 만족하는 첫 variant 의 팔레트/이름을 쓴다
- [ ] 장소 이름 표시(HUD)에 variant 접미사 반영 — "사무실 (야간)"

### 상황별 맵 목록

| 맵 | 상황 | 무엇이 달라지나 |
|----|------|----------------|
| `office` | 낮 / 야간 | 팔레트, NPC 유무, 복합기 사진, 조명감 |
| `home` | 2장 밤 / 4장 밤 | 문자 알림 유무, 차 아이템 |
| `lobby` | 아침 / 퇴근 후 | 픽업대 커피, 카페 직원 NPC |
| `control_room` | CCTV 열람 / 사내망 조사 | 보안 담당자 위치, 열람 가능한 자료 |
| `corridor` | 야간만 | 절반만 켜진 조명(팔레트), 청소 카트 |

## 5) 맵 디자인 원칙 (1h)

좌표를 손으로 쓰기 전에 규칙부터 정한다. **JSON 좌표는 직관이 안 통해서, 규칙이 없으면 금방 무너진다.**

```text
그리드    32px. 모든 좌표와 크기는 32의 배수 (사람·소품만 예외)
뷰        960 × 640 — 한 화면에 20 × 20 타일
맵 크기   최소 960×640(한 화면), 최대 1280×960 (그 이상은 걷는 시간만 늘어난다)
통로      최소 64px (플레이어 24px + 여유). 32px 통로는 벽에 끼는 느낌이 난다
가구 간격 상호작용 거리가 48px이므로, 다른 반응을 원하는 오브젝트끼리는 96px 이상 띄운다
밀도      맵 하나당 상호작용 3~6개. 2개 이하면 빈 방, 7개 이상이면 뭘 봐야 할지 모른다
문        벽에 붙여서 배치하고, 문 앞 96px 은 비운다 (도착하자마자 가구에 끼지 않게)
스폰      반드시 빈 바닥. 검증 스크립트가 벽·solid 충돌을 잡는다
```

- [ ] 맵마다 **한 눈에 보이는 랜드마크** 하나 (엘리베이터·복합기·정수기) — 길 찾기의 기준점
- [ ] 막다른 길 금지. 들어간 곳은 나올 수 있어야 한다
- [ ] 조사할 것이 있는 오브젝트는 동선 위에 두고, 장식은 벽면에 붙인다
- [ ] 종이에 20×20 그리드를 그려 배치한 뒤 좌표로 옮긴다 (바로 JSON에 쓰지 않는다)

## 6) 스프라이트 규격 (선택, 1.5h)

여유가 있을 때만. **없어도 게임은 완성 상태를 유지한다.**

```text
인게임    48 × 64 px (@2x — 논리 크기는 24×32, 픽셀 밀도만 2배)
시트      192 × 64 × 2 = 192 × 128  (가로 4방향 down/left/right/up, 세로 2프레임)
초상      256 × 256   대화창·컷씬용 얼굴
전신      720 × 1080  (네이티브 240×360 을 정수배 ×3 — 1080p 화면용)
가구      32의 배수, 오브젝트 rect 크기와 동일
경로      public/assets/images/characters/<id>.png          주간 스프라이트
          public/assets/images/characters/night/<id>.png    야간 팔레트
          public/assets/images/characters/hires/<id>.png    전신 1080p
          public/assets/images/portraits/<id>.png           초상
          public/assets/images/objects/<id>.png             가구
색        옷 1색에서 명암 4단(광/기본/그늘/짙은그늘) + 외곽선 + 강조(사원증 금색)
```

**@2x 로 두는 이유**: 논리 해상도 960×640 캔버스를 CSS로 확대하므로, 스프라이트를 24×32 로 만들면
고DPI 화면에서 뭉갠다. 48×64 로 만들어 24×32 크기로 그리면 선명하다 (`imageSmoothingEnabled = false` 유지).

**실루엣 구분**: 색만으로는 야간 팔레트에서 구분이 흐려진다. `characters.json` 의 `art` 로
머리(short/bob/long/tied)와 액세서리(none/cap/glasses/tie/badge)를 지정해 실루엣을 다르게 만든다.

- [ ] `SpriteCache` — 이미지 1회 로드 후 재사용, 실패 시 색 폴백
- [ ] 걷기 애니메이션은 이동 중일 때만 프레임 교대 (0.2초)
- [ ] 픽셀 뭉개짐 방지: `ctx.imageSmoothingEnabled = false` (이미 꺼져 있다)

## 리스크

| 리스크 | 대응 |
|--------|------|
| 그림에 시간을 다 쓴다 | 1단계(색 사각형)에서 플레이 테스트를 끝내고, 스프라이트는 §6으로 미룬다 |
| NPC가 통로를 막아 진행이 막힌다 | `solid: true` NPC는 통로 폭 96px 이상인 곳에만. 검증에서 통로 폭 확인 |
| 조건 오타로 NPC가 영영 안 나온다 | "항상 거짓" 조건 탐지를 검증에 넣는다 (§7) |
| 상황별로 맵을 복제해 데이터가 갈라진다 | variants + 오브젝트 조건으로만 처리 (§4) |
| 스프라이트가 없어서 화면이 깨진다 | 렌더러 폴백 필수. 에셋은 항상 선택 사항 |

## 시간이 부족하면 자르는 순서

```text
1순위로 버림 → 걷기 애니메이션 · portrait
2순위       → 스프라이트 전체 (색 사각형 유지)
3순위       → 팔레트 variant (야간도 낮 색으로)
4순위       → NPC 조건부 재배치 (한 자리에 고정)
```

**절대 자르지 않는 것: NPC로 말 걸기(인물 단서가 엔딩 조건이다), 스프라이트 없을 때의 색 폴백,
JSON만으로 배치·수정 가능한 상태.**
